# 平台自查与交接清单（DSH / Antigravity 共用）

本文件是**交接清单，不是已填写的报告**。目前已完成 Codex 的接入架构与自查记录 [codex.md](codex.md)，以及 ChatGPT 普通 Chat 的候选评估 [chatgpt.md](chatgpt.md)（候选、默认禁用）。DSH 与 Antigravity 的自查尚未开始，不预填结论，也不伪造“已支持”。

## 1. 适用方式

以后把本文件分别交给 DSH 与 Antigravity 的独立调查会话，要求它们：

1. 各自建立 `docs/platforms/dsh.md` 或 `docs/platforms/antigravity.md`，按本清单逐项写结论。
2. 同步更新 [docs/platform-contracts.md](../platform-contracts.md) 的能力矩阵，以及 [P0 evidence summary](../p0-evidence-summary.md) 的已知/待验证/阻塞。
3. 只写事实与证据；没有证据就写“未验证/阻塞”，不写“应该可以”。
4. 三个平台使用同一套 adapter 契约：capabilities / listSessions / inspectSession / submit / waitForResult；平台差异只放在 adapter 内，不污染 coordinator。

本文件不要求现在开始任何新调查。当前任务只是文档交接。

## 2. 硬边界

- 不安装 CLI、扩展、依赖或新软件；不认证新账号。
- 不修改平台配置、数据库、日志、认证材料或现有项目。
- 不启动/注册新服务，不启用 remote control/调试端口。
- 不做模型定时唤醒、heartbeat 轮询或空转等待。
- 不读取、复制或输出凭据、cookie、token、私人会话正文。
- 不用模拟点击/截图冒充真实接口；检测到 exe 不等于接口可用。
- **真正发送探测必须得到用户明确授权**；未授权只做只读帮助、源码、元数据和现有证据核对。
- 任何发送前都要先证明目标会话身份与关联方式；不偷偷新建 thread/fork/克隆历史来“绕过”附着问题。

## 3. 必答清单

每个平台按同一顺序输出，缺一项就标“未验证”，不要用推测补齐。

| # | 检查项 | 必须给出 | 证据要求 |
|---|---|---|---|
| 1 | 版本与实例 | 产品/CLI 版本、实例标识、安装路径或端点、是否桌面/CLI/服务 | 命令输出或文件版本信息；注明采集时间 |
| 2 | 会话 ID 来源 | 会话 ID 的真实来源、格式、稳定标识；标题为何不能作身份 | 源码/协议字段/只读查询；不接受“界面上看到”作为唯一证据 |
| 3 | 枚举接口 | 列出既有会话的只读入口；分页/过滤/权限；没有就明确“无” | 命令/协议/固定 commit 源码；区分“官方公开/本机私有/仅推断” |
| 4 | 向既有会话投递 | 能否向用户已选会话发送；是否新建会话/克隆；receipt 形态 | 实测需授权；未授权只做只读候选评估 |
| 5 | request/turn/message 关联 | 我方发送 ID 如何映射到平台 turn/message；能否证明“这次投递对应这个结果” | 唯一 ID、回读字段、关联链路；候选必须标候选 |
| 6 | 终态与等待 | 完成/失败/取消/审批等待分别是什么事件；长轮询还是推送；超时行为 | 事件名/状态字段/只读观测；不把“无新消息”当完成 |
| 7 | 人工输入与审批 | 外部人工插话能否识别；审批能否读取/批准/拒绝；不能时 UI 如何明示 | 字段/计数/事件来源；没有来源就标 unsupported/partial |
| 8 | 重连与恢复 | 断线后如何核对在途 turn/结果；unknown 是否禁止重发；是否可安全继续 | 对账步骤与失败路径；不承诺 exactly-once |
| 9 | 桌面对话 vs CLI 克隆 | 控制的是原桌面对话，还是另起进程克隆历史；差异和限制 | 官方原文/源码/实测；克隆不得写成接管原会话 |
| 10 | 暂停竞争 | 发送前 gate、持久化 sending、发起 submit 是否连续；pause 能否插在中间 | 实现规则或待实现设计；已接收任务不可假装撤回 |
| 11 | 日志与隐私 | 只保留哪些 ID/状态/错误码；正文是否复制；清理策略 | 脱敏样例；不得整段复制私人日志 |
| 12 | 结论分级 | 已知/部分验证/阻塞；什么变化会使结论失效；下一最小测试 | 每条结论对应证据位置，不能只写“可用” |

## 4. 证据分级写法

每个结论必须带标签，不能混写：

- **代码**：固定 commit 的源码/协议定义；写明仓库、SHA、文件。没有 SHA 的 README 只能算“文档”，不能算代码证据。
- **实测**：本机在某个时间执行过的命令/调用及脱敏输出；必须能重复，且不包含私密正文。
- **推断**：由字段或进程存在推导出的可能路径；必须写“未验证”，不能进入能力矩阵的“已验证”列。

同一行可以同时有代码与实测，但要分开写。例如“协议有 turn/completed（代码）｜本机连接未收到（实测未通过）”。

## 5. 交付格式

建议每个平台文档固定包含：

1. **结论摘要**：会话枚举 / 投递 / 完成识别 / 关联 / 人工输入 / 审批 / 重连，每项标 native / candidate / unsupported / blocked。
2. **入口与版本**：可接续的会话标识、实例标识、采集命令。
3. **能力矩阵**：按第 3 节 12 项逐行；附证据链接。
4. **最小验收**：在同一已选会话上的启动→完成→结果回读链路；失败/取消/审批/人工插话/暂停/断线的反例。
5. **阻塞与下一步**：缺哪一层、需要用户授权什么、哪些结论会因版本变化失效。
