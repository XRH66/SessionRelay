# 05 · 许可证、依赖与发行边界

本页是基于已读许可文本的工程检查单，不是针对所有衍生发行场景的法律意见。复制或发行前应再核查实际取用文件、子包和传递依赖。证据见 [LX01、LX02、LX15、WEB03](07-evidence-and-corrections.md)。

## 1. 不能把 Apache-2.0 / MIT 当成当前自由二选一

固定 LoopX 快照中，根 LICENSE 为 Apache License 2.0，pyproject 和 DSH 插件 package.json 均标 Apache-2.0。NOTICE 说明：**截至 v0.4.7 的历史发行曾采用 MIT，历史文本保留于 LICENSE-MIT。** 这不是当前所有新代码都提供 MIT 或 Apache 二选一的证据。

本轮没有逐文件审计历史归属，也没有核查所有子包依赖。对选中的现行代码，按已确认的 Apache-2.0 来源记录，而不是仅因 SessionRelay 根许可为 MIT 就删除上游声明。

## 2. 实际复用时的检查项

Apache-2.0 第 4 节要求分发时附许可、保留适用声明、对修改文件明确说明变更，并按条件保留 NOTICE 归属信息。项目自身代码仍可清晰声明其许可，但引入的第三方部分及其义务不能被根目录一句 MIT 覆盖。[LX15、WEB03]

建议在真正复制代码时建立：

- third_party/loopx/ 下的许可与 NOTICE 副本，或等价的明确第三方声明位置；
- 文件级来源记录：仓库、提交 SHA、原始路径、原始 blob/摘要、采用理由；
- 修改说明：类型映射、删去的宿主逻辑、Windows 适配和行为变化；
- 依赖清单及对应许可，发行包内可查看的第三方声明。

本轮只提交研究文字、定位与建议，没有复制实现代码，因此不假装已经完成 vendoring 清单。将来从 Python 逻辑翻译为 TypeScript 的衍生实现，也不能仅因更换语言就当成完全无来源代码。

## 3. 运行依赖与产品外壳

| 采用方式 | 已知负担 | 当前建议 |
|---|---|---|
| 提取小范围 TS 校验 | Node 标准库及少量内部 helper；仍需解析传递依赖 | 优先；本轮未编译验证这些文件可独立运行 |
| 采用完整 DSH 插件 | 指定 DSH peer 版本与 Node；与宿主插件体系、LoopX CLI 配合 | 不直接自动安装；先验证窄桥是否足够 |
| LoopX 子进程治理 | Python 3.11+、Node 22.22.3+、所选扩展、版本和数据兼容 | 后置隔离试验，不默认成为安装要求 |
| 整体桌面底座 | 实验性 Tauri 外壳、React、两项本地 HTTP 服务；Windows 预览仍涉及手动 CLI 安装 | 与当前 Electron/无监听目标冲突，须显式产品决策 |

以上来自 LX01、LX02、LX09、LX11。`dependencies=[]` 仅说明 Python 默认运行依赖的打包字段，不能翻译成“整个产品没有依赖”。也不把网页/桌面预览说明当成已经在用户 Windows 环境通过验收。

## 4. 发布时必须保留的边界

本项目当前要求无新 HTTP listener、无独立系统服务、不开机自启。路线 A 可以保持该边界；路线 B 应先证明可以通过按需子进程完成所需操作；路线 C 需要重新批准产品约束，不能借“融合”悄悄增加后台服务。

不默认继承上游安装器、自动升级、遥测、账号配置迁移或浏览器服务。每项外部网络与持久配置行为都应单独列入评估。对 DSH，如果使用宿主已有的认证 MCP/HTTP 接口，这是出站调用；不等于允许 SessionRelay 新开监听端口。

Windows 验收还应覆盖子进程清理、路径编码、长路径、符号链接/reparse point、文件锁和包升级回滚。所读 LoopX 协作文档对部分安全文件导出明确限定已支持的 POSIX 宿主，不能把其 no-follow 方案未经验证移植为 Windows 安全承诺。[LX04]

## 5. 许可与发行结论

许可证不是本轮所见的明显整合禁区，但也不是“开源就随便拼”。工程上可保留 SessionRelay 的原创部分和产品身份，同时准确声明引入的 Apache-2.0 代码；具体复制范围、依赖和发行方式确定后，再完成文件级许可检查。当前不修改 SessionRelay 根 LICENSE。
